# PDFForge Lite Marketing Plan

## Positioning

PDFForge Lite is an HTML-to-PDF API for small teams that do not want to operate Chromium. Lead with the practical pain: deployment dependencies, serverless timeouts, memory spikes, and print CSS surprises.

## Ideal Customers

- Small SaaS teams adding invoice, receipt, report, or export PDFs
- Agencies shipping client portals and recurring reports
- Solopreneurs who need PDF generation but cannot maintain browser infrastructure
- No-code builders using n8n, Make, Zapier, Airtable, Bubble, or Webflow

## First Wedge

Start with three specific use cases:

- Invoice PDFs from existing HTML
- Client reports generated by scheduled jobs
- No-code workflow PDFs from HTTP request steps

Generic PDF generation is too broad. The first promise should be: send the HTML you already have and get back a reliable PDF.

## SEO Themes

- HTML-to-PDF API
- Puppeteer alternative for PDF generation
- Playwright PDF API
- n8n PDF generation
- Make.com PDF automation
- Zapier PDF generation
- invoice PDF API
- client report PDF generator
- serverless PDF rendering

## Launch Motion

1. Publish a practical demo and docs with curl, JavaScript, Node, and no-code examples.
2. Add three use-case pages: invoices, client reports, and no-code workflow PDFs.
3. Record a short walkthrough showing a PDF generated from the playground and curl.
4. Do direct outreach to 50 small SaaS founders and agencies with a concrete migration offer.
5. Launch publicly after at least three external users have generated PDFs successfully.

## Copy

One-liner: PDFForge Lite is an HTML-to-PDF API for teams that do not want to operate Chromium.

CTA: Send HTML. Get a PDF. Keep Playwright, browser dependencies, and usage tracking behind one endpoint.

No-code CTA: Turn workflow HTML into downloadable PDFs from n8n, Make, Zapier, or any HTTP request step.

Objection answer: This is not magic infinite serverless scale. It is a reliable container-first MVP you can deploy, observe, and harden.
